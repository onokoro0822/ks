# 週次進捗レポート

毎週の進捗報告スライドを作るための記録フォルダ。
1週間に1ファイル、Markdownで書き、Claude Codeでpptxに変換する。

## ファイル構成

| パス | 内容 |
| --- | --- |
| `TEMPLATE.md` | 週次記録のひな形 |
| `YYYYMMDD.md` | その週の記録。日付は報告日（日本時間） |
| `figures/YYYYMMDD/` | スライドに載せる図のコピー（任意） |
| `pptx/YYYYMMDD_進捗報告.pptx` | 生成したスライド |

## 毎週の流れ

1. 週の初めに `TEMPLATE.md` を `YYYYMMDD.md`（次の報告日）としてコピーする。
2. 作業のたびに、Claude Code・Codex・本人の誰かが該当する節へ追記する。
3. 報告前に Claude Code へ次のように頼む。

   > `weekly_reports/YYYYMMDD.md` から進捗報告のpptxを作って

4. 生成された `pptx/YYYYMMDD_進捗報告.pptx` を確認し、必要なら手で直す。

## 書き方のルール

- `###` 見出し1つがスライド1枚になる。見出しは短いタイトルにする。
- 図は `![説明](パス)` で書く。パスは `syuron/` からの相対パス。
  `ppflow_change_automatic/` などの入れ子リポジトリの図は外側のGitに入らないため、
  残したい図は `figures/YYYYMMDD/` にコピーしてから参照する。
- 数値は、確認した出力ファイルやテストと一緒に書く。未確認・仮説には【仮】を付ける。
- 外部資料は「出典:」の行にURLまたは資料名を書く。

## `ppflow_change_automatic/docs/progress/` との関係

`docs/progress/`（CURRENT / NEXT / DECISIONS / CHANGELOG）は研究と実装の正式な記録で、
ここはそれを週単位で報告用にまとめたもの。内容が食い違う場合は `docs/progress/` を正とする。
週次記録を書くときは、対象期間の `CHANGELOG.md` と `NEXT.md` を元にしてよい。

## スライドの体裁（`進捗.pptx` に合わせる）

- 16:9、Officeテーマ、フォントは游ゴシック。
- タイトルは左上に小さめ（32pt）。表紙・目次は付けない。
- 1枚に1テーマ。図は左、式・説明・出典URLは右に置く。
- 式は大きめに、出典URLは小さく下部か右側に置く。
- `## 今週やったこと` などの節ごとに、先頭に節タイトルだけのスライドは作らない。
  ただし `## 課題・相談したいこと` と `## 来週やること` は、それぞれ1〜2枚にまとめる。
